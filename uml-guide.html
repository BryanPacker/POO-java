🎓 Entendendo Diagramas UML de Classes

O que você vai aprender: Como ler um diagrama UML, entender os relacionamentos entre classes e, depois, implementar no código.

1️⃣ A Anatomia de uma Classe no Diagrama

Uma classe em UML é representada como um retângulo dividido em 3 partes:

┌─────────────────────┐
│ Cliente │ ← Nome da classe
├─────────────────────┤
│ - nome: String │ ← Atributos (privados)
│ - cpf: String │
├─────────────────────┤
│ + Cliente(...) │ ← Métodos (públicos)
│ + getNome(): String │
└─────────────────────┘
Símbolos importantes:
- = privado (private)
+ = público (public)
# = protegido (protected)

2️⃣ Os Três Tipos de Relacionamentos

▲ Herança (extends)

O que significa: Uma classe É UM tipo de outra classe.

Símbolo: Seta sólida com triângulo vazio apontando para a superclasse.

Filme → ▲ → Midia
(lê-se: "Filme é uma Midia")

No código:

public class Filme extends Midia { // Filme herda tudo de Midia }
✅ Use herança quando há um relacionamento "É UM"
❌ Não use se a relação é "TEM UM"

●━ Composição (has-a)

O que significa: Uma classe TEM DENTRO DELA outra classe. O objeto interno é criado NO CONSTRUTOR.

Símbolo: Linha sólida com losango sólido (●) no lado de quem TEM.

Orcamento ●━ Entrega
(lê-se: "Orcamento tem uma Entrega")

No código:

public class Orcamento { private Entrega entrega; // Atributo public Orcamento(String cidade, int prazo) { this.entrega = new Entrega(cidade, prazo); } }
✅ Use composição quando um objeto precisa de outro DENTRO dele
💡 O objeto interno é criado no construtor

○━ Associação (uses)

O que significa: Uma classe USA/CONHECE outra classe. Pode passar como parâmetro ou guardar referência.

Símbolo: Linha sólida simples (sem losango).

Orcamento ○━ Cliente
(lê-se: "Orcamento trabalha com Cliente")

No código:

public class Orcamento { private Cliente comprador; // Recebida no construtor public Orcamento(Cliente comprador, ...) { this.comprador = comprador; } }
✅ Use associação quando uma classe usa outra mas não a cria
💡 É passada como parâmetro

3️⃣ Lendo Cardinalidade (Multiplicidade)

Os números nas extremidades das linhas indicam QUANTOS objetos podem estar relacionados:

Símbolo Significado Exemplo
1 Exatamente 1 Um Orcamento tem exatamente 1 Entrega
0..1 Zero ou 1 Um Orcamento pode ter 0 ou 1 endereço de cobrança
* ou 0..* Zero ou mais (muitos) Um Orcamento tem 0 a 5 itens
1..* Um ou mais Um Orcamento tem 1 ou mais itens
Orcamento ●━ 0..* ItemSetup
(Um Orcamento tem de 0 a vários ItemSetup)
public class Orcamento { private ArrayList<ItemSetup> itens; public Orcamento(...) { this.itens = new ArrayList<>(); } }

4️⃣ Analisando o Diagrama do Exercício

Cliente ○━ Orcamento
(Orcamento usa Cliente - passado no construtor)

Orcamento ●━ Entrega
(Orcamento tem uma Entrega - criada no construtor)

Orcamento ●━ 0..* ItemSetup
(Orcamento tem vários ItemSetup - criados e adicionados depois)

ItemSetup ▲ Peca
(Peca é um ItemSetup - herança)

ItemSetup ▲ Montagem
(Montagem é um ItemSetup - herança)

5️⃣ Passo a Passo: Do Diagrama para o Código

Exemplo: Implementar Orcamento

Passo 1: Leia os atributos do diagrama:

Orcamento{ - Orcamento(solicitante: Cliente, cidade: String, prazoDias: int) - getClienteSolicitante(): Cliente - setSolicitante(solicitante: Cliente): void - getGarcia(entrega): String - getprazoEmDias(): int - adicionaItem(item: ItemSetup): void - removeItem(item: ItemSetup): void - calculaValorTotal(): double }

Passo 2: Identifique os relacionamentos:

  • ✅ Cliente é parâmetro (Associação) → atributo privado
  • ✅ Entrega é criada aqui (Composição) → atributo privado
  • ✅ ItemSetup é coleção (Composição) → ArrayList

Passo 3: Escreva a classe:

public class Orcamento { private Cliente solicitante; private Entrega entrega; private ArrayList<ItemSetup> itens; public Orcamento(Cliente solicitante, String cidade, int prazoDias) { this.solicitante = solicitante; this.entrega = new Entrega(cidade, prazoDias); this.itens = new ArrayList<>(); } public void adicionaItem(ItemSetup item) { itens.add(item); } // ... outros métodos }
